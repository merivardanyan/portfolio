    Hue Hunt

    See a color for 3 seconds, then rebuild it from memory. A daily puzzle with a Wordle-style result grid.

    • React
    • Node
    • SQLite
    Live demo: Hue Hunt Source: Hue Hunt
    Case study: Hue Hunt

    Problem

    Make a daily game that is quick, fair and shareable.

    Architecture

    A plain-ESM core (seeded RNG, color math, scoring) imported by both the React app and the Node server. The client submits guesses, never scores. node:sqlite stores submissions with one row per player per day.

    Highlights

    • Perceptual scoring with CIEDE2000 in Lab space, not RGB distance
    • Seeded daily puzzle shared by client and server; the server recomputes scores from raw guesses
    • Keyboard-operable 2D color picker and a canvas-rendered share card

    Key decisions

    • The server recomputes every score from the raw guesses, so a submitted score can’t be tampered with
    • ΔE2000 maps to a 0-100 score that matches how different two colors look to people
    • The static demo swaps the HTTP adapter for a local one that fakes percentiles from a seeded distribution

    Stack

    React, Node, SQLite

    Ghostwriter

    Write something, then share a link that plays it back keystroke by keystroke, typos and hesitations included.

    • React
    Live demo: Ghostwriter Source: Ghostwriter
    Case study: Ghostwriter

    Problem

    Show how a text was written, not just the result, without a server ever seeing the content.

    Architecture

    The editor records insert/delete events with relative timestamps. A codec delta-encodes and deflates them into the URL hash. The player rebuilds state from periodic snapshots for scrubbing.

    Highlights

    • Event-sourced document: the text is a fold over a keystroke log
    • Compact binary encoding + CompressionStream + base64url fits a replay in the URL
    • Snapshot checkpoints make seeking fast instead of replaying from zero

    Key decisions

    • Deliberately serverless: the link is the product and the content never leaves the URL
    • Varint delta encoding before compression keeps most replays under the URL comfort zone
    • Live region announces playback state, not every character

    Stack

    React

    Fair Share

    Paste the receipt, send one link, everyone taps what they ate, and tax and tip settle themselves in real time.

    • React
    • Node
    • SQLite
    Live demo: Fair Share Source: Fair Share
    Case study: Fair Share

    Problem

    Splitting a group bill is error-prone and nobody wants to install an app at the table.

    Architecture

    A pure split function (bill, claims) → per-person totals, shared by client and server. Node + ws broadcasts versioned patches; clients request a snapshot when they detect a version gap.

    Highlights

    • Integer cents with largest-remainder allocation, so totals reconcile to the penny
    • WebSocket sync with versioned patches, optimistic updates and gap recovery
    • Static demo syncs between tabs with BroadcastChannel, no server needed

    Key decisions

    • Money is never a float: all math is integer cents
    • No accounts: each participant gets a secret token, and claims are authenticated against it
    • The same UI runs on a BroadcastChannel adapter for the static demo

    Stack

    React, Node, SQLite

    Seed Sequencer

    A garden where every plant is a loop. Plant seeds, prune leaves, and share the song as a link.

    • Vue
    • Pinia
    • Web Audio
    Live demo: Seed Sequencer Source: Seed Sequencer
    Case study: Seed Sequencer

    Problem

    Make music creation instant and impossible to get wrong, and make sharing a song as easy as sharing a link.

    Architecture

    Vue 3 + Pinia hold the garden; a scheduler queues notes 120 ms ahead on the audio timeline and a rAF loop maps the audio clock back to the UI so plants sway exactly on their notes.

    Highlights

    • Look-ahead scheduler on the AudioContext clock, so timer jitter never reaches the audio
    • Undo/redo through a command stack that merges slider drags
    • A full garden packs into at most about 220 URL characters

    Key decisions

    • Everything is quantized to a pentatonic scale, so random input still sounds good
    • Synthesized voices and a generated reverb impulse: zero audio files
    • Roving-tabindex grids and aria-pressed toggles; motion is off under reduced motion while audio keeps playing

    Stack

    Vue, Pinia, Web Audio

    Throttle Lab

    Fire requests at four rate-limiting algorithms side by side and see exactly why the fifth request gets a 429.

    • Vanilla JS
    • Web Components
    • Node
    • SQLite
    Live demo: Throttle Lab Source: Throttle Lab
    Case study: Throttle Lab

    Problem

    Rate-limiting trade-offs are usually explained with static diagrams that hide the edge cases.

    Architecture

    Algorithms are pure step functions over JSON state, so the library, the demo server and the browser share one implementation. Web Components render each lane on canvas.

    Highlights

    • A dependency-free Node rate-limiting library with pluggable memory and SQLite stores
    • The same algorithm code drives the in-browser visualization on a simulated clock
    • Click any denied request for a plain-English explanation of why

    Key decisions

    • Injectable clock makes every algorithm deterministic and testable
    • No framework on the frontend, on purpose
    • Standard RateLimit-* and Retry-After headers on the real server

    Stack

    Vanilla JS, Web Components, Node, SQLite

    Hot Take Court

    Submit your hottest take, let the internet be the jury, and get a verdict card: guilty of being wrong, or acquitted.

    • PHP
    • MySQL
    • SQLite
    • Vanilla JS
    Live demo: Hot Take Court Source: Hot Take Court
    Case study: Hot Take Court

    Problem

    Opinions are fun to argue about, and a verdict card gives each argument something worth sharing.

    Architecture

    Server-rendered PHP 8 with session auth, CSRF tokens and rate limiting; MySQL schema with a SQLite twin for local runs. The static demo reimplements the rules on localStorage behind the same API shape.

    Highlights

    • Framework-free PHP: front controller, router, controllers, repositories, PDO prepared statements
    • One vote per user per case enforced by a database primary key, with counters updated in the same transaction
    • Verdict cards render as SVG in-page and as PNG for link previews

    Key decisions

    • Constraints live in the database, not just in PHP
    • Trending ranks recent votes with time decay; cases close after 72 hours
    • Verdict share links in the demo embed a snapshot, so they work without a server

    Stack

    PHP, MySQL, SQLite, Vanilla JS

How I build

Four habits, each with proof you can check

01

Architecture first

Pure core modules, thin adapters at the edges, and one API module per frontend.

Hue Hunt’s React app and Node server import the same scoring core.
02

Accessible by default

Semantic HTML, visible focus, full keyboard support and reduced-motion handling from the first commit.

Seed Sequencer's music grids are fully playable from the keyboard.
03

Fast on real devices

Small bundles, no layout shift, and no third-party requests unless they pay for themselves.

Throttle Lab’s whole interface ships in about 11 KB of gzipped JavaScript, with no framework.
04

Tested where it matters

Unit tests concentrate on the logic that would hurt if it broke, rather than chasing a coverage number on the UI.

Fair Share's split math is tested down to single-cent remainders.
